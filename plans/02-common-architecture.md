# 02 · 四类多方块共用架构

## 1. 共享与隔离

四类结构共享几何基础设施，不共享错误的过程模型。

共享：结构扫描、主从绑定、能力代理、拆损/重建、存档同步、端口注册、世界内诊断、低频调度。

隔离：

- 釜使用均混多相库存与反应状态；
- 塔使用按高度分段的气液/气固库存；
- 池使用表面负荷、溢流和底泥状态；
- 炉使用固体料层、炉气、主熔体和炉渣状态。

## 2. 物质表示

### 2.1 水溶液与浆料

继续使用单一 `chemicaladdon:mixture` Forge Fluid。水相库存采用引擎状态；水、离子、分子等游戏显示由它派生，悬浮与沉底记录固相位置。元素、电荷、溶剂量及新格式存档往返遵循引擎契约，不要求各物种“份额之和”强行等于流体 mB。

### 2.2 纯流体与气体

适合 Create 管网运输的纯液体/气体使用普通 Forge Fluid；压力是容器状态，不为每个压力注册流体变体。

### 2.3 固体与炉料

可运输固体使用 item。炉内允许把 item 配方批次转换为抽象固体料层，不逐实体模拟颗粒。

### 2.4 熔体与炉渣

炉内使用专用熔体库存，支持主熔体/炉渣分层和不同出口。只有确实需要管道运输的熔体才注册 Forge Fluid，避免为每种中间炉渣制造流体注册爆炸。

## 3. 化学与配方边界

- 自发水相平衡、沉淀、回溶和络合由现有 IPhreeqc 适配层承担。
- 需要点火、供电、催化、跨价态驱动、煅烧、焙烧和冶炼的过程由白名单配方层承担。
- 配方声明输入输出、最低结构能力、温压窗口、内部件、热量、速率和副产物；不绑定“机器名称”。
- 同一配方可以允许多个拓扑，但应给出效率或控制差异，例如批式釜吸收与填料塔吸收。

### 3.1 水相单一权威迁移方案（2026-09）

目标是在明确支持的物种、温压和浓度范围内，新增水相化学主要增加经过校验的数据，不再增加 Java 物质分支。用户明确要求：以化学引擎为优先，允许破坏旧接口，由游戏适配引擎；模组尚未上线，不编写旧存档兼容或迁移。以下为目标与实现契约，完成态仍只看 `docs/progress.md`。

**状态权威**：IPhreeqc 的完整水相状态决定下一拍。保存元素及价态池、溶剂量和恢复所需的 H/O、电荷等内核状态，不能把总元素重新编码成代表离子后再以 `pH 7 charge` 重建。四域中的水相显示是派生视图，不能反向决定化学。仅增设元素总量缓存不足以达到此目标。删除 dominant-ion 反馈、补水闭体积及人为补 H/OH 修正存储电荷的路径；初始投料也必须使用明确的化学定义。

**运输契约**：随 mixture 保存的内核水相快照必须带参考 mB。普通比例抽取沿用 Create 的复制 NBT、改变 amount 规则，恢复时以实际量/参考量缩放水相；不能让 1 mB 样品带出整釜物质。库存缩放与混合优先使用内核 `MIX_SOLUTION`，之后由化学拍负责反应，不平均 pH/pe、不拼接代表离子。普通 `MIX` 会立即触发包括氧化还原在内的平衡，不能用于无反应的运输。参见 [USGS MIX_SOLUTION](https://water.usgs.gov/water-resources/software/PHREEQC/documentation/phreeqc3-html/phreeqc3-33.htm) 与 [MIX](https://water.usgs.gov/water-resources/software/PHREEQC/documentation/phreeqc3-html/phreeqc3-27.htm)。同一液流的探测与实际抽取必须保持相同 NBT 身份。任何新状态格式都要版本化。

**物料事务**：投料、气液传质、配方消耗、过滤夹带、蒸发与结晶必须有明确的输入、输出和所作用的相。先在候选态提交物料变化与求解，成功后更新状态和视图；失败不消费输入、不发布新读数。不能通过“猜测显示变化”长期维持两套权威。

**模型分工**：酸碱、络合及允许快速平衡的相统一使用同一活动度模型下的平衡数据；慢速氧化还原、成核、生长及催化过程使用有来源的速率模型。固相的热力学身份与悬浮/沉底的空间位置分开。气液平衡与有限速传质也分开：平衡决定驱动力，装置决定接触和速率。不能直接删除动力学限制、令所有候选相和氧化态瞬时全平衡。

**热量**：建立与物料同一事务的能量账，再迭代求解温度与化学状态。数据库中用于平衡常数温度修正的反应焓，不等于已实现绝热反应温升；缺少一致的热数据时必须标注模型范围。

迁移顺序：

1. **完整状态与物料接口**：引擎定义新状态及缩放、混合、投料、取样、移除水等操作；静置、比例运输及新格式存档重载使用完整状态。新桶、配方等外部物料从声明构造新态。缺状态或不支持的旧格式明确拒绝，不从旧四域猜测恢复。
2. **游戏全面适配**：迁移混合、投料、配方、蒸发、分离及湿饼母液的真实调用链；删除全量四域重建化学的旧接口。尚未有模型的操作明确拒绝且不吞料，不能暂时回退旧算法伪装正常。前两步共同构成可交付的核心重构。
3. **统一化学数据**：审核支持物种与数据库的覆盖、价态、活度参数、温度依赖及亚稳语义；用内核相模型替换独立结晶曲线的化学判定，保留有依据的成核/生长动力学。
4. **气液与热耦合**：有限气相库存、双向传质、开闭边界、能量闭合进入同一过程状态；设备仅提供边界条件和传质参数。

验收必须比较“连续原生求解”与“分步、运输、存档后续算”，覆盖元素和溶剂守恒、pH/pe、固相、零量边界以及多釜共享会话隔离；测试通过数量不能替代这些物理契约。未知物种、缺失模型及求解失败应可诊断，不以补水、补离子或跳过失败相伪装成功。

### 3.2 内部价态池封装与计量审计（2026-09）

保留 PHREEQC 后端的介稳伪元素池及 KINETICS，不实施删除内部伪元素或另建受约束平衡求解器的路线。伪元素是引擎实现细节，游戏投料使用真实化学式；真实化学式、后端组分及显示物种的转换集中在引擎数据与接口中，不在游戏类中维护多套物质分支。

每个内部池声明代表的真实原子组成。液内反应的净计量展开这些组成后必须守恒，包括 H/O；界面反应须明确外部物料交换，不能假作封闭体系守恒。修正计量后还须以原生求解验证价态变化，不能仅凭反应名称或速率中出现 Fe、I、Mn 就宣称已实现对应反应物的计量消耗。速率标定与热力学数据的可靠程度分别记录。

本阶段继续遵守 §3.1 的原生状态、运输及失败事务要求，不增加旧档兼容；完成态与尚未解决的动力学限制登记于 `docs/progress.md`。

I/Mn/S 通道的后续验收须覆盖实际消耗与产物：以同输入、同候选相的零时间步作为基线，区分初始平衡与动力学增量；分别测试氧化剂不足、还原剂不足及耗尽后续算。碘统计溶解物种与晶体中的全部 I；锰区分高锰酸根的计量还原与 Mn(II) 催化，按适用条件验证 Mn(II)/MnO₂；硫统计硫化物、亚硫酸盐、硫酸盐与单质固相，有氧通道还须验证有限溶解氧的消耗。不能用速率门控或总元素守恒代替这些断言，也不能把某一酸度下的产物强制推广到全部条件。新增产物通过统一相定义进入原生固相账本，覆盖运输、存档与分离，禁止按反应名称在 Java 中补发物品。

## 4. 结构能力匹配

建议配方匹配结构：

```text
requiredCapabilities: [mixed_volume, sealed, pressurized, gas_dispersed,
                       settling_area, solid_bed, molten_bath, catalyst_bed]
requiredParts: [...]     requiredMaterial: {...}
temperature: {...}       pressure: {...}
```

控制器根据实际结构生成能力集合。这样新增配方不需要新增机器类，新增内部件也可以服务多条工艺。

## 5. 端口原则

- 所有结构件可以代理能力，但实际处理必须尊重端口类型、方向和高度。
- 输入/输出锁定相位，防止 Create 管道在组成变化时频繁断流。
- 模拟与执行分离：`SIMULATE` 不得改变相锁、配方进度或存档。
- 结构失效时按破口高度保留或洒漏；炉式熔体采用更严格的安全策略。

## 6. 材料系统

壳体、内衬和内部件提供属性，而不是固定机器等级：

- 耐温、耐火、耐压；
- 耐酸、耐碱、耐氯、耐磨；
- 导热或隔热；
- 结构强度和维护寿命。

首版只实现会产生玩法差异的属性。没有诊断、维护或替代方案的耐久消耗不得上线。

## 7. 热、压力与流量

- 使用统一 J 账本，物料显热、反应热和相变潜热进入同一容器能量。
- 压力采用稳定、可预测的简化模型；支持分压供给和泄压，不追求真实可压缩流网络。
- 批式按离散反应步结算；连续流用有效容积/流量估算停留时间。
- 塔的级数、池的面积负荷和炉的料层/熔池拥有各自公式，不套用釜的容量倍率。

## 8. 性能预算

- 所有化学与过程结算低频执行；渲染插值独立。
- 不做世界方块级流体、逐颗粒或逐塔板连续模拟。
- 结构扫描只在搭建/破坏时发生；正常 tick 使用缓存拓扑。
- 大结构按预算分摊求解；单结构长期平均不得因体积线性遍历全部方块。
- 每种模板在施工前建立性能哨兵：空载、满载、同区块多台和区块卸载恢复。

## 9. 新格式与接口变更

模组未上线，本轮不实现旧存档读取、转换或双轨兼容。引擎需要的状态、单位和接口优先于现有游戏接口，允许破坏性更新；游戏中的容器、物料、配方和仪表跟随适配。新格式必须版本化并验证合法性，旧格式或缺失模型明确报告，不静默重建、丢料或使用退役引擎。

## 10. 共用验收契约

每种模板至少验证：最小/最大结构、错误结构诊断、任意控制器层、能力代理、端口方向、拆损重建、内容守恒、区块重载、客户端同步、自动化管线和性能预算。
