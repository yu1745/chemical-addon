>

## 1. 一句话目标

这是一个以 Create 世界内工程为语言的工业化学附属：玩家用少量通用多方块、内部件、管线、仪表和回流，把矿物、水、空气与副产物组织成可诊断、可扩建、可闭环的工厂。

## 2. 基础决策

整个模组只设四种通用多方块拓扑：

1. **釜**：单一混合容积，处理液体、气液、浆料、压力、结晶。
2. **塔**：沿高度分段，处理逆流吸收、蒸馏、汽提和固定床催化。
3. **池**：大面积与重力过程，处理澄清、沉降、废水和缓慢晶种分解。
4. **炉**：高温固体、料层、炉膛与熔融浴，处理煅烧、焙烧、烧结和冶炼。

现实中的“高压釜、碳化器、蒸馏塔、石灰窑、高炉”等是配置与推荐蓝图，不是新的结构种类。气体吸收统一由带气体分布器的釜承担，不再注册独立吸收塔。第五种结构必须证明四种拓扑都无法表达，并至少服务三个重要工艺族。

## 4. 不再沿用的结论

- 不沿用固定“61 物种、52 反应、39 方块”等内容上限。
- 不沿用“火法冶金出圈”“氧化铝必为终点”“回转窑永久砍掉”等先验裁剪。
- 不沿用以某条现实流程命名开发单元的排期。
- 不沿用“所有纯物质都必须是 Forge Fluid”等已经与当前代码不符的旧表述。
- 不恢复配方选择 GUI、控制面板或每种设备一个控制器的旧路线。

内容不是无限扩张：每条产业线必须通过 [08-industry-map.md](08-industry-map.md) 的准入检查，再进入版本计划。

## 5. 当前事实与未来计划的边界

- `docs/progress.md` 中已经完成的釜、池、结晶、过滤、仪表、mixture 与 IPhreeqc 适配继续保留。
- 新计划不承诺立即重构已有注册 ID；例如现有结晶器可长期兼容，但设计身份归入釜式预配置。
- 塔和炉尚未完成；计划中不得写成已实现。
- 每次开工前先核对当前源码与成熟 Create/生态实现，再把实际完成态写入 `docs/progress.md`。

## 6. 最高优先原则

1. **通用结构优先于专机名称。**
2. **空间布局必须改变过程。** 端口高度、内部件和尺寸不能只是装饰。
3. **产品必须有用途。** 没有消费端的化学品不进入主线。
4. **失败必须可诊断。** 玩家应知道缺料、欠温、过压、液泛、夹带或炉况错误。
5. **先纵向可玩，再横向扩内容。** 每种新能力先完成一条端到端工厂。
6. **化学精度服务游戏。** 保存守恒、趋势和工业逻辑，不追逐无收益的连续模拟。
