# 03 · 物质抽象模型 v2（离子基底 · 物种 = 模式）

> 文档状态：**current**（v2 物质模型权威版；S1–S3f 已完成）

> **v2 权威版，取代 v1**。v1 =「全量流体注册 + 组合系统 + 釜内流股」三轨。
> v2 推翻 v1 的三个核心假设：浓/稀是物种、解离↔重组往返、以及「釜内这杯东西要有名字」。
> 落地进度：规则引擎 v1 + 离子基底 S1–S3f 已完成（见 `docs/progress.md`）；本文即 **v2 目标模型的权威定义**。

---

## 0. 一句话模型

**釜/管道里只有一种「溶液」可存储：离子多重集 + 水 + 分子溶质。**

**「物种」退化为「命名组成模式」：只用于配方匹配、名字、颜色、创造栏桶的默认配比，不参与釜内存储，也不参与显示。**

浓/稀不是物种，是浓度。解离、重组、优先级补丁——全部不存在。

---

## 1. 为什么推翻 v1（三个已暴露的痛点）

1. **浓/稀同离子签名**：v1 里浓硫酸和稀硫酸是两个注册流体，但解离后都是 `2H⁺ + SO₄²⁻`，离子层面不可区分；重组时只能靠「优先原物种」补丁猜回哪个——补丁是症状，不是设计。
2. **「恢复名字」是伪需求**：`Na₂CO₃ + KNO₃` 混在一起、无沉淀无反应时，就是一杯 Na⁺/K⁺/CO₃²⁻/NO₃⁻ 的离子汤，**没有也不需要名字**；引擎里任何「把混合物还原成物种名」的代码都是在满足一个不存在的问题。
3. **组合系统与釜内流股双轨并行**，但都不表达「任意浓度」：`components`（brine = 水 + 岩盐）与 `ReactorContents`（物种 + 浓度）是两套东西，而工业上浓/稀、饱和/不饱和**全是浓度，不是身份**。

## 2. 核心数据结构

### 2.1 mixture FluidStack NBT

```
mixture FluidStack（chemicaladdon:mixture，仍只注册这一个元流体）:
  Ions:      { "H+1": 2, "SO4-2": 1, "Na+1": 5 }        // 离子多重集，GCD 约分 parts
  Molecules: { "chemicaladdon:water": 10,
               "chemicaladdon:carbon_dioxide": 2 }        // 溶剂 + 分子溶质（中性分子物种）
  Color:      <int ARGB>       // 由离子/分子色派生；无色离子不贡献 → 清水
  Temperature: <int>           // 独立键，所有 FluidStack 共享（照旧，非 mixture 专属）
```

- `Ions` 与 `Molecules` 是**同一个逻辑比例空间**的两个命名域：`totalParts = Σ(Ion parts) + Σ(Molecule parts)`，每个组分的绝对量 = `total × part / totalParts`。`Mixture.deriveAmounts` 机制照旧复用，**只是把 key 空间从「物种 id」换成「离子 id + 分子物种 id」**。
- **电中性是硬不变量**：任何 mixture 恒满足 `Σ(charge × part) = 0`（比例层面校验即可，比例中性 ⟺ 派生量中性）。写入 / 反应 / 填装 / 配方产出都必须过校验，违反即拒绝并报错——这是 bug 而不是玩法。

### 2.2 釜/罐 = 相列表

`ReactorTank` 的 `List<FluidStack>` 语义不变，但含义明确为**相列表**：

- 1 个 aqueous mixture（离子 + 水 + 溶解态分子溶质）
- N 个不互溶液相（油 / 汞，见 §5.4）
- M 个纯气相（H₂ / O₂ / N₂ / Cl₂，密闭釜的气相空间，不溶于水相）

分相按密度分层、按相先后抽出，互溶性决定能否共线输送（沿用 D18）。

> ⚠️ **现状缺口（未实现）**：`ReactorTank.collapseIfNeeded()` 当前**无差别合并**所有条目——气体、不互溶液体、互溶溶液统统并进单一 mixture（物理上错：气体不溶于水、油水不互溶）。后果有二：① renderer 的「气体挂顶」分支（`isLighterThanAir`）在常态下是死代码；② 「抽出哪一相」由列表顺序（先入先出）决定，无密度排序。**正主是 D18**：把 `collapseIfNeeded` 改成「只合并同互溶组、跨组/气体保持独立相」+ `drain` 按密度排序解析抽相（底口重相 / 顶口轻相）。这是 S1 之后的第一块。

## 3. 离子与分子溶质

### 3.1 离子表（内部 id + charge + color，不注册）

| 离子 | charge | 颜色 | 说明 |
|---|---|---|---|
| H+1 | +1 | 无色 | 酸根 |
| OH-1 | −1 | 无色 | 碱根 |
| Na+1 / K+1 / Ca+2 | +1 / +2 | 无色 | 主族阳离子 |
| Cl-1 / SO4-2 / CO3-2 / NO3-1 / NH4+1 | … | 无色 | 阴离子 / 铵根 |
| *(future)* Cu+2 | +2 | 蓝 | 有色离子 → 溶液颜色 |
| *(future)* Fe+3 | +3 | 黄褐 | 有色离子 → 溶液颜色 |

- **主线无机离子全是无色**：怎么混都是清水，身份被隐藏——这是化学的魅力，也是玩法驱动（逼玩家用化验手段）。
- 离子是**内部身份**，永不注册为物种/流体/物品，颜色表数据驱动（离子 JSON 或 `gen_species.py` 数据表，`FluidColors` 扩展为按 id 查色）。

### 3.2 分子溶质 vs 纯气体

- **水**：溶剂，`Molecules` 里的中性物种，唯一默认。
- **分子溶质**：CO₂ / SO₂ / NH₃ / HCl(g) 的溶解态——存进 `Molecules`（不电离）；其电离（H₂CO₃、NH₄⁺…）由规则引擎按条件动态处理，**不做固定解离表**（这是 v1 解离表的替代）。
- **纯气体**：H₂ / O₂ / N₂ / Cl₂ 等**不溶于水相**，作为纯流体相独立运输（保留现有注册），不进 mixture。

## 4. 物种 = 模式（species JSON 语义变更）

species JSON 从「物种定义」改为**「命名组成模式」**：

```jsonc
{
  "formula": "H2SO4", "phase": "LIQUID",
  "ions": [ {"ion":"H","charge":1,"count":2}, {"ion":"SO4","charge":-2,"count":1} ],  // 中性配比
  "solubility": [ ... ],                             // 溶解度曲线（g/100g 查表，结晶用；不迁 equilibria）
  "equilibria": [ ... ],                             // 常数平衡条目（沉淀/络合/弱电解质，见 §8.2）
  "solute": "..."                                  // 冷却析出的固体目标（析晶 → Sediment 沉底域）
  "miscibilityGroup": "aqueous",
  "phaseTransition": [ ... ],
  "color": 0xRRGGBB                                  // 桶/物品默认 tint（可选）
}
```

**模式只有四个职责：配方匹配、名字（JEI/创造栏/护目镜引用）、颜色、桶默认配比。** 不参与釜内存储与显示。`components` 字段废弃——混合物本身就是组成。

### 4.1 已注册 38 流体分两类

| 类 | 物种 | 处理 |
|---|---|---|
| 纯物质 | 13 气体、导热油（14 个） | **照旧注册流体**；**水 = 原版 `minecraft:water`**（不重复注册，`Solution.WATER` 指向它） |
| 溶液 / 浆料 | 酸/碱/盐溶液、氨水、brine、浆料（23 个） | **降级为模式别名**，不再单独注册流体 |

**浓/稀合并为单签名**：`dilute_sulfuric_acid` + `concentrated_sulfuric_acid` → 单模式 `sulfuric_acid`（=`2H⁺+SO₄²⁻`）；HCl、HNO₃ 同理。`brine`、`ammoniated_brine` 也由模式取代（它们是同一离子汤的不同配比/加氨状态）。

## 5. 浓度、浓/稀、颜色

- **计量单位 = 摩尔当量（mole-equivalent）**：1 mB × 化学计量系数 = 1 个抽象计量单位，比例正确、绝对数无关。**全模组不引入 mol / g/mol**（见 §10 否决「真实摩尔」）——反应算的是比例，不是摩尔数。
- **内部求解网格 = 1/10000 mB（`Chemistry.UNIT_PER_MB = 10⁴`，2026-08 U14）**：求解器、比例 tag、规则引擎全部工作在 unit 域，浓度分辨率 10⁻⁷。定标锚点＝无机化学中还要建模的最弱水解 Mg²⁺（Ka≈10⁻¹¹·⁴，产物 ~6×10⁻⁷）；再弱（Ca²⁺/Na⁺，10⁻¹³ 以下）现实不可观测、明确不建模。10⁻⁷ 同时为将来 Kw 条目（纯水 pH 7）留门。保持整数：电中性精确、GCD 比例身份、确定性求解；`distribute` 乘积 ≤1.56e18（long 内 6 倍余量），unit 派生对异常大堆做软钳制。**mB 视图（渲染/管道/桶）照旧是传输粒度**——细粒度活在比例 tag 里，跨 tick 持久化。
- **量纲阶梯与「中间面额」不变量（2026-08 U15 定案，已实现）**：阶梯为 unit(10⁻⁴ mB) → 流体 mB → **晶粒(62.5 mB，1/16 物品)** → 物品(1000 mB)。**任何频繁跨越物品↔流体边界的量，都应有中间面额可表达**——否则会出现「要么 0 要么一整桶」的操作断层（投晶种、沉淀池出料零头、小批量投料都会撞上）。已落地（U15）：8 可结晶固体的晶粒物品变体（粉碎轮 1→16）、`dissolveItems` 双面额溶解/投种；后置钩子 = 底排口零头打包晶粒。晶种语义：**锁死非消耗**——整坨取出只发整物品，沉底余量 <1000 mB 时种留锅内终身自接种。62.5 mB 在 10⁴ 细网格上精确保存（与奇数总 mB 混合时受 mB 视图整数量化，±0.5 mB 级、不累积）。
- **浓度 = 离子单位 / 水单位**（单一无量纲比值），不设独立字段——存储层天然表达任意浓度。
- **溶解度（冷却结晶）量纲约定**：`solubility` 照抄现实 g/100g，引擎用「分子式单元 / 水」算浓度，阈值 = `gPer100g / 100 × K`（K 是唯一全局缩放旋钮，声明 `1 分子式单元 ≡ 1 g`、`1 mB 水 ≡ 1 g`，忽略摩尔质量）——不引 mol/g/mol，但保留现实相对溶解度比例与温度趋势。
- **浓/稀 = 浓度阈值的派生标签**（显示与配方门槛用），不是身份。
- **颜色从组成派生**：无色离子 → 清水；有色离子（Cu/Fe）→ 对应色；分子溶质可带色；水无色。

### 5.1 混合度（MixDegree）已删除：混匀是釜的局部状态，不是流体属性

v1 曾把「混合度 MixDegree」塞进 mixture NBT（0=未混匀色带、1=混匀），并为此配了传输冻结 hack、按量加权合并、色带渲染、护目镜 mix% 显示和 4 个测试。**已整体删除**（2026-08）。

- **判定**：物理上不存在。两杯互溶液体倒进罐子不搅会短暂分层，但**一旦抽出就是均匀的**——管道/桶/储罐里没有「还有 40% 没混匀」这种东西。一个概念需要写 hack 对抗传输系统，就是它在错误的地方。
- **保留内核**：搅拌→反应速率的「传质」玩法**下沉为釜的局部 `stirring` 字段**（RPM → 速率系数 0.3–1.0，接进 `tickReaction` 进度），来源是 Create 机械混合器 / whisk；**不做会累积的进度条**——传质速率是转速的瞬时函数，不是「攒到 100%」。
- **否决「未混匀禁止抽出」**：现实永远能抽液；混没混匀影响的是**抽出哪一层**，这是 §7 分相/倾析（D18）的职责，不是 MixDegree。
- **分层语义交给 D18 互溶性**：离子+水一旦进同一 mixture 就是均相；真正持久的分离是「不互溶 → 分相 → 按密度抽」。

## 6. 显示与诊断（世界内交互铁律）

- **釜内无名、清水**（或离子色）。谁也不能从外表看出是什么——**这正是化学的魅力**。
- **dev 模式 overlay 才显示离子列表**（诊断用，非玩家常态）。
- **测量诚实性原则（2026-08 定案，U17）**：玩家侧仪表/试纸只许读**物理上诚实的间接量**——密度/波美度、沸点升高、pH、离子检出阈值（试纸=消耗性阈值探测器）、浊度、颜色/焰色。**引擎内部状态（SI/speciation/物种身份）对玩家侧仪器不可见**——直读即上帝视角，知识必须由玩家经分析化学挣来（校准运行 / 手册计算 / 试纸质检）。现有护目镜「饱和态行（SI）」**降级为 dev 化验模式**（`ASSAY_ON`），玩家常态路径只有目视、物理量仪表、消耗性试纸三类。蒸发等温过程里唯一会动的信号是沸点/密度等总浓度函数——这正是间接量的价值：有盲区，盲区就是玩法。
- **名字只出现在三个真实边界**：
  1. 配方 / JEI / datagen 引用（= 模式名）
  2. 创造栏桶（= 打包好的已知配比）
  3. **物理分离的出口**（沉淀 → item、蒸馏 → 纯流体、分相 → 某相）
- 玩家要知道釜里是什么，靠：世界内仪表 / 指示灯 / 护目镜（化验手段）+ 反应结果观察（沉不沉淀、变不变色、分不分层）。这与 AGENTS.md「世界内交互优先、GUI 弱化」铁律一致。

## 8. 配方层与规则引擎

- **白名单配方**输入输出引用模式 id，引擎把模式**展开**成 `{离子集 + 水}` 匹配 / 产出——JEI / datagen / KubeJS 全保留（D13）。
- **规则引擎删掉 `dissociate` / `recombine`**：持久态就是离子集，引擎退化为「改离子多重集 + 调水量」的纯涌现。
- **规则引擎 v2 = 统一平衡条目 + 质量作用求解器**（语义与 log_k 出处：**PHREEQC**，USGS 公有领域，见 THIRD_PARTY.md）：
  - **所有常数平衡共用一条数据形状**——`equilibria` 条目（见 §8.2）：沉淀、络合、弱电解质（水解家族）都是「反应式 + log_k」，引擎只有一个质量作用求解器，不是每种平衡一个机制。
  - **沉淀** = 离子积 `Q = Π c^计量数`（`c = 分子式单元 / 水 mB`，无量纲）超过 `K = 10^(log_k + MINERAL_LOG_OFFSET)` 时析出**至 Q = K**（log 空间比较防下溢）——留饱和母液，不析干 → 进 `Suspended`；逆向欠饱和即回溶。**两旋钮制**：`MINERAL_LOG_OFFSET = -2` 仅作用于矿物条目（Ksp 量纲归一，log_k ≤ −5 在 1000 mB 水中残留 <1 单位＝「完全析出」）；**水相条目（络合/弱电解质）用原始 log_k**——β/Kb 本就以内禀浓度比表达，再平移会把 Kb 压到整数分辨率下限以下成死条目。`SOLUBILITY_SCALE` 照旧管溶解度曲线（第三旋钮，曲线族专用）。
  - **中和** = `H⁺ + OH⁻ → 水`（移除离子对，水增，放热）——仍是独立步骤（化学计量而非平衡）。
  - **结晶** = 溶解度曲线（`solubility` 表，形状是曲线不是常数，**不迁 equilibria**）判定过饱和，**只析出过剩部分**（`maxFormable − floor(阈值×水)`，留饱和母液）→ 进 `Sediment`；逆向欠饱和回溶。
  - **复分解 / 同离子效应 / 络合掩蔽** = 没有专门逻辑，是平衡条目联立的涌现结果。
- **动力学（两速化学，2026-08 U14）**：水相快平衡（酸碱/络合/绝大多数沉淀，毫秒级）**瞬时解**（PHREEQC 立场，缺省）；慢过程按**亲和律**每求解步限速：
  - **结晶域默认动力学**：生长步长 ≤ `CRYSTAL_RATE_FRACTION(0.1) × 水量 × (c/c_sat − 1) × 搅拌`，几何逼近永不过冲；**成核门槛** `NUCLEATION_AFFINITY(0.5)`——无晶种且过饱和 <50% = **亚稳**（骤冷不析出），一粒晶种即塌缩（接种玩法）；过门槛后首晶 ×`NUCLEATION_PENALTY(0.05)` 慢成核；**回溶瞬时**（细晶表面动力学快）；**蒸干规则**：水尽则曲线物种全部析出（煮干出盐）。常数全在 `Solution`（与 SOLUBILITY_SCALE 同族旋钮）。
  - **平衡条目可选 `"rate"`**（单位/反应tick @25°C）：`步长 ≤ rate × 2^((T−25)/25) × 搅拌 × |Q/K−1|`，每求解步只推一次；缺省 0 = 瞬时（现役数据全部缺省，零回归）。
  - **搅拌**：`stirringCoefficient`(0.3–1.0，U5 钩子) 乘进一切动力学速率（扩散控制），与配方层同一语义；`Speciation.rateLimited` 位报告"热力学该动但动力学卡住"（护目镜可显示）。
  - **意义**：U8 连续流 τ=V/Q 从此有物理意义（停留时间决定转化率）；配合热量记账（§12）后 `k(T) 翻倍 × 放热` 即自加速链。
- 「优先原物种」补丁已删除——那步运算本身不存在了。

### 8.1 引擎边界（设计决策，2026-08 定案）

> **自发的归规则引擎，需要驱动的归配方引擎。**

| 归规则引擎（倒进去就发生） | 归配方引擎（给了活化条件才发生） |
|---|---|
| 酸碱中和、沉淀/溶解、结晶/回溶、络合、（后置）水解/弱电解质、水蒸发 | 氧化还原、热解/煅烧、电化学（电解）、催化反应 |

- **pe/Eh 平衡红氧明确否决**：热力学平衡会消灭动力学亚稳态（H₂/O₂ 共存、NH₃ 室温不分解全是动力学屏障保护的），平衡红氧 = 无条件点火，直接摧毁玩法。红氧（氯碱电解、接触法、奥斯特瓦尔德）全走配方层的热/催化剂/电条件匹配。
- **活度系数（Debye-Hückel / Pitzer）再次否决**：无量纲约定 + 全局旋钮（`SOLUBILITY_SCALE` / `LOG_K_OFFSET`）就是替代品。
- **盐类水解后置；弱电解质已解封首条**（2026-08 U14）：`NH₃ + H₂O ⇌ NH₄⁺ + OH⁻`（Kb 10⁻⁴·⁷⁵，原始 log_k）——氨水从「完全电离」改「部分电离」，强酸滴弱碱/强碱赶氨由中和步骤的弱电解质通道按化学计量完成（经 Kw 介导、推动力近无限）。盐类水解（Cu²⁺/CO₃²⁻ 等）仍后置，格式已通逐条可加。
- **结晶水**（CuSO₄·5H₂O 析出应耗水）：维持「饱和母液近似为水」简化。

### 8.2 equilibria 条目 schema（v2 权威格式）

```jsonc
"equilibria": [
  // 反应式 token：" + " 连接（带空格，离子 id 如 Cu+2 不受影响）、"=" 分两侧；系数前缀；相位后缀 (s)
  // log_k = 反应按书写方向的平衡常数（固体/溶剂活度=1）。矿物按溶解方向书写（同 PHREEQC PHASES）：log_k = log Ksp
  { "reaction": "limestone(s) = Ca+2 + CO3-2", "log_k": -8.3, "delta_h": -10.6 },
  { "reaction": "Cu+2 + 4 chemicaladdon:ammonia = [Cu(NH3)4]+2", "log_k": 12.6 }  // 络合：书写方向 = 生成方向，log_k = β
]
```

- 条目挂在任意物种 JSON 上（组织归属无所谓，`SpeciesManager` 汇总成全局列表——同 PHREEQC 的 PHASES / SOLUTION_SPECIES 组织方式）；**求解顺序：水相条目（络合/弱电解质）先、矿物按 log_k 升序后**——络合先于成核，氨掩蔽铜即此顺序的涌现（松弛求解对顺序敏感，此顺序编码该化学）。
- `delta_h`（van't Hoff 温度修正）字段预留，v1 不算。
- token 里裸写 `water` = 溶剂（活度 1，不进 Q 也不被搬运）。
- 旧 `ksp` 字段已删除（迁移为 equilibria 条目）；`solubility`+`solute` 保留（结晶曲线，形状不同）。

## 9. 旗舰场景复验

1. **索尔维闭环**：氨盐水 = mixture `{Na⁺, Cl⁻, NH₄⁺, OH⁻, CO₃²⁻} + 水` → 碳化（引擎移除 Na⁺ + HCO₃⁻ → NaHCO₃↓）→ 过滤机出滤饼 → 煅烧 → 纯碱 + CO₂。全程 mixture，无物种映射。
2. **合成氨循环**：N₂ + H₂ 纯气相 → 高压釜（气相反应，N₂/H₂/NH₃ 是纯气体，不进 aqueous mixture）→ 转化率上限 → 未反应气循环。合成氨在气相，独立成章（06 需补「气相流股」）。
3. **浓硫酸稀释事故**：浓硫酸桶（高 `2H⁺+SO₄²⁻`/水比）倒水 → 浓度骤变 → 放热事故。禁忌规则**按浓度判定**，天然区分浓/稀——事故机制第一次有了真正可判定的输入。

## 12. 风险与开放问题

- **电中性校验边界**：桶 / 配方 / 第三方 mod 填装都要过校验；纯气体等非电中性来源走独立相，不进 mixture。
- **固相语义（已定，2026-08）**：mixture 除 `Molecules` + `Ions` 外有两个固相域——**`Suspended` 混悬**（快速沉淀，釜内浑浊不澄清）+ **`Sediment` 沉底**（降温结晶，直接沉底）。沉淀 → `Suspended`、结晶 → `Sediment`（按生成规则分，不靠 JSON 手标）；过滤机抽 `Suspended` 吐固体 item，`Sediment` 留给沉淀池/底排口（「mixture + 固体项」方案，非独立流体）。
- **混合固体的物品承载（已定 2026-08，U15 已实现）**：固相域按物种分格只是**账本，不是分离**——物理上沉底的晶体混作一团，未付出分离劳动就取出 = 混合物。规则：
  - **未分离的混合固体由 mixture 流体承载**（Suspended/Sediment 域），物品边界只在取出时出现；
  - **取出必须整坨、禁止选物种**；**严格判定：域内单物种 → 纯物品；含任何第二物种 → 混合盐渣物品**（NBT 成分比例，复用 mixture 的 GCD ratio-tag 身份机制，tag 相等才堆叠——确定性引擎保证同喂料同渣可堆叠）；
  - **机器只做相分离，物种分离永远是化学活**——纯物品的三条挣取路线 = 时序分批取出（分步结晶窗口）/ 化学除杂（沉淀剂先行）/ 重结晶循环；**否决：按物种选择性出料、纯度阈值判定**（机器替玩家化验 = 上帝视角，与 §6 测量诚实性冲突）；离散粗品固定配比物种方案亦不再需要（NBT 身份机制已覆盖任意成分）；
  - 混合盐渣的玩家可见信息遵守 §6 测量诚实性：统一命名 + 颜色渲染（物理可观测量），成分百分比仅 dev 化验；**溶解即化验**（扔回水里按 NBT 精确展开回离子域，试纸可检）；
  - 残余离子对的归宿是**补数据**（MgCl₂ 等苦卤盐曲线物种，U15 已补：MgCl₂ 新物种、CaCl₂ 补曲线——蒸干不再有干离子残留），不是造新承载。
- **湿饼母液夹带与洗涤（已定 2026-08，U16.5 待实施）**：固液分离的不完美 = **机械夹带**，不是共沉淀——湿饼体积的声明分数（残液率，如 30%）是晶隙母液，取出结算时按当时液相浓度比例分摊进取出物；residue NBT 扩「母液相」（水+离子），GCD ratio-tag 堆叠与「溶解即化验」照旧。取出纯度判定语义不变（**只判成分、不判浓度**）：单物种固体 + 夹带相仅剩水 → 纯物品，含任何非水第二成分 → 盐渣——洗涤把母液置换成清水后单物种饼自动变纯物品，机器没有纯度阈值上帝视角。洗涤两条涌现路线：①釜内**再浆洗涤**（分液口滗不清晶隙滞留液；加清水→再悬浮→再滗，按残液率几何衰减；清水回溶产品的产率损失由既有回溶引擎免费给出——洗 NaCl 饼丢产率、洗 CaCO₃ 饼不丢）；②过滤机**置换洗涤**（洗水穿饼替换夹带，置换效率声明常数）。洗涤终点 = 滤液电导率不再降（电导率计的首个真实场景）。**否决共沉淀/吸附/晶格取代**：无可靠通用数据、与夹带在玩家可观测层面几乎不可区分、破坏确定性求解——夹带已给九成玩法价值。
- **气相反应**（合成氨、氨氧化）不在 aqueous mixture 内，需在 06 补「气相流股」模型（与 aqueous 规则引擎并列）。
- **萃取（液-液分配）为独立系统，不入规则引擎 v2**（2026-08 决策）：互溶性分相已有（D18，规则引擎只解 aqueous 相、非极性液相为旁观），但萃取需要①溶质分配系数（可复用 equilibria 条目形状 + `(o)` 相后缀，如 `solute(aq) = solute(oil), log_k`）、②多液相联立求解、③「溶在油里」的存储语义——三件都是新地皮。萃取走独立萃取器容器（搅拌=界面传质速率），**绝不与水溶液反应同釜执行**；排期见 11 弹性轨道。
- **反应热量纲（U16 已修，2026-08 实现）**：热是能量记账——`Solution.energyJ`（double，负值=冷却需求），声明 1 unit ≡ 1 g、c=4.18 J/unit·°C（与溶解度曲线声明同款哲学），`ΔT = Q/(feedUnits × c)`（feed 基准=投料四域总量，反应吸热的是当时那锅料）。中和热 3172 J/对（57.1 kJ/mol ÷ 18 g/mol；直接对与弱电解质驱动对同价）；蒸发潜热 2260 J/unit（`evaporateWater` 记负账——开口釜排汽冷却余液：无热源自熄、有热源持续沸腾，自限负反馈）；配方 `deltaHeat` 同口径（JSON 声明=参考一桶（10⁷ units）体的温升，实际 `ΔT = deltaHeat × (一桶/釜内总量)`，质量反比缩放，现有 150/100 两个配方语义不变）。浓则跨沸点（1:1:1 中和 ΔT≈253°C 自沸）、稀则温升个位数（大釜稀释），自持与热失控成为涌现（配合 U11 泄压阀、k(T)×放热自加速链）。验收：双向 GameTest + `EnergyLedgerTest` 4 例。
