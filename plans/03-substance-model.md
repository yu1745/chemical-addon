# 03 · 物质抽象模型（Create 架构版，双轨 + 组合系统）

> **本文件是附属的地基**，2026-09 依生态盘点与用户决策重写。
> 三个关键决策：
> - **全量注册 Forge Fluid**：61 种物种全部注册为 Forge 流体，运输/储存层 100% 复用 Create 管道/泵/罐（D12 修订）；
> - **组合系统借鉴匠魂 JSON 修饰器机制**：溶液/混合物 = 基础物种 + 组分条目，数据驱动、可组合、可扩展；
> - **釜内流股**：只有进入反应容器的流体切换为自研表示（反应有进度、中间态、温度、压力、浓度、催化）。

---

## 1. 分层架构总览

```
┌─ 运输/储存层（全部 Forge Fluid，Create 原生）────────────────┐
│  · 61 种物种 = Forge Fluid（液体/气体/浆料统一为流体，         │
│    FluidType 属性区分：密度、温度、粘度、气体渲染）             │
│  · Create 管道/机械泵/阀门/FluidTank 多方块/喷头/排水口 直连    │
│  · 简单混合（溶解/稀释/吸收）= 罐内组合配方（匠魂合金式）        │
│  · 固体（盐/纯碱/滤饼/矿石）= item，走 Create 传送带/漏斗      │
├─ 反应层（自研：釜内流股模拟）───────────────────────────────┤
│  · 釜内容器 = 多物种共存流股（匠魂 SmelteryTank 式 List + 状态）│
│  · 每物种一个条目：量、浓度；容器共享：温度、压力、进度          │
│  · 反应：进度 0→100%、中间态、ΔH、催化、转化率上限              │
│  · 仅此处有「化学变化」；釜口 ⇄ Forge Fluid 自动转换            │
└──────────────────────────────────────────────────────────┘
```

## 2. 物种注册表（全部 = Forge Fluid）

每个物种 = 一个 Forge Fluid 注册项 + JSON 元数据（组合系统，见 §5）：

| 流体属性（FluidType） | 化学属性（JSON 元数据） |
|----------------------|------------------------|
| 密度（气体为负→上浮渲染） | 化学式、基准相态 |
| 温度（热流体显示热色） | 沸点/熔点（1 atm 查表） |
| 粘度（浆料高粘→泵速慢） | 溶解度曲线（温度分档） |
| 颜色/透明度（气体用雾化渲染） | 危险类别（腐蚀/毒/易燃/氧化） |
| 可桶装（→S08 罐装化学品物品） | 比热系数、ΔH 参考 |

61 种物种清单见 [08-substance-catalog.md](08-substance-catalog.md)。**气体 = 负密度流体**（Create 6.0.8 无气体系统，此为自研规避）；渲染上气体流体用半透明+粒子化纹理，管道内表现为「轻雾流动」，可接受。

## 3. 为什么不再需要「流股管道」

v1 计划自建流股管道的两个理由，在全量流体注册设计下消失：

| v1 理由 | 双轨化解 |
|---------|---------|
| 温度/压力无法表达 | 管道只运标准态；热/高压只存在于釜内（就近加工，不长途泵送——直觉合理） |
| 多组分溶液无法表达 | 组合系统：溶液 = 基础物种 + 组分条目（见 §5），作为独立流体物种注册（如「氨盐水」就是注册流体），管道照常运输 |

代价：浓度/温度维度的「中间状态」不能进管道——**热物料就近加工**成为设计约束（也符合化工常识：高温物料不长途输送）。

## 4. 釜内流股（自研表示，唯一化学变化发生地）

### 4.1 釜内容器结构（概念层）

```
ReactorContents {
  species: [ {speciesId, amount(mB), concentration(可选)}, ... ]   // 多物种共存，匠魂 SmelteryTank 式
  temperature: °C            // 容器共享
  pressure: kPa              // 密封容器内由气相量×温度推导
  progress: {recipeId, 0..1} // 当前反应进度（可暂停/中断）
  intermediates: [...]       // 分步反应中间态（如 SO₃、NO₂）
  catalyst: {item, durability}
  sealLevel: NONE/SEALED/HIGH_PRESSURE
}
```

### 4.2 为什么釜内必须自研（用户决策：反应有进度有中间态）

- Forge FluidStack 无温度/压力/进度/浓度字段（NBT 可塞但不该滥用，Create 管道/罐会把它当普通流体混流）；
- 化学反应需要：**进度条**（玩家能看到反应进行到一半）、**中间态**（接触法先 SO₂→SO₃→再吸收）、**放热升温**（ΔH 反馈到温度）、**压力积累**（密封容器）；
- 这些是釜的领域对象，与传输层的「搬运」语义天然分离。

### 4.3 釜口转换

- 液体口/气体口（Forge Fluid）→ 进入釜 → 自动转为流股条目；
- 反应产物 → 出釜口 → 转回 Forge Fluid 进管道；
- 固相产物（滤饼/晶体）→ item 从物品口出（漏斗/传送带）。
- 转换是纯数据映射（物种 ID 相同），无信息损失。

## 5. 组合系统（借鉴匠魂 JSON 修饰器机制，核心架构）

> 目的：**溶液/混合物免注册爆炸**。氨盐水 = 水 + NaCl + NH₃ 两个组分，不用为每个组合注册独立流体。
> 做法：组合作为一种**独立流体物种**注册（「氨盐水」是注册流体），但其**内部结构**（组成、配比、可离解性）由组合系统数据驱动定义；组合的合法性（溶解度）、行为（反应性）按组分 hook 分发。

### 5.1 架构映射（匠魂修饰器 → 化学组合）

| 匠魂修饰器系统（证据见 sa-4 盘点） | 化学组合系统 |
|----------------------------------|-------------|
| `data/.../tinkering/modifiers/*.json` + SimpleJsonResourceReloadListener | `data/<mod>/chemistry/species/*.json`：物种定义（含组成/组分列表） |
| ModifierId extends ResourceLocation | SpeciesId（namespace:path），天然支持多 mod 扩展与数据包覆盖 |
| 工具 NBT 只存 `(id, level)` 列表，行为懒解析 | 釜/容器只存 `(speciesId, amount, concentration)` 条目，行为懒解析 |
| 单修饰器内多模块按 hook 合并（ModuleHookMap + merger） | 单物种内多组分行为合并（溶解度=取组分最严、密度=加权和） |
| 跨修饰器调用方循环累积（ToolAttackUtil） | 跨物种反应由反应引擎循环匹配配方 |
| ModuleHook<T>（id/filter/merger/default）+ register() 第三方扩展 | 化学 hook：SOLUBILITY / REACTIVITY / PHASE / DANGER / CATALYST，可注册新 hook |
| 合并器语义（All/First/Any/Max/Compose） | 浓度加和 vs 饱和截断 vs 取最严危险等级，一行配置 |
| each_level 参数化 | 每 mol 贡献量参数化 |
| datagen provider（AbstractModifierProvider） | species JSON datagen provider |

### 5.2 组合规则（概念层）

```
species 盐水 {
  base: 水
  components: [ {NaCl, 饱和浓度 26%}, ... ]
}
组合判定：流体「氨盐水」= base 水 + components [NaCl, NH₃]
  · 合法：各组分浓度 ≤ 溶解度（查表，饱和截断）
  · 行为：DANGER hook = 各组分取最严（NH₃ 腐蚀+毒）
  · 反应性：REACTIVITY hook 决定与何物反应（配白名单）
  · 可离解：加热/稀释可拆回组分（蒸发→盐析出为 item）
```

### 5.3 罐内组合（运输层，匠魂合金式）

- Create FluidTank/沉淀池等**非釜容器**内：多流体共存时按「组合配方」（数据驱动，类似 AlloyRecipe）判定——如 SO₂ 气+水 → 亚硫酸液、NH₃ 气+水 → 氨水；
- 触发：低频 tick 检查（匠魂每 4 tick），白名单配方匹配即消耗输入产出输出；
- **无温度/进度**（简单混合才走这里）；涉及放热/中间态的一律进釜（避免两套模拟打架）；
- 与釜的分工：**罐内组合 = 溶解/吸收/中和的「快路径」，釜 = 主工艺反应的「慢路径」**。

## 6. 渲染与交互（双轨白拿）

| 场景 | 渲染 | 归属 |
|------|------|------|
| 管道/罐内流体 | Create 原生流体渲染（液面、流动动画） | **零自研** |
| 釜内液位/温度/气相 | 釜窗口自绘（液面分层色带、温度色、雾气粒子） | 自研（10-multiblock §4） |
| 浆料 | 高粘度流体渲染 + 管道慢速流动 | 零自研（流体属性） |
| 固体物流 | 传送带/漏斗原生 | 零自研 |

## 7. 与世界的边界

| 边界 | 规则 |
|------|------|
| 水入口 | Create 泵抽 vanilla 水 → 即「水」流体物种（无需转换，天然互通） |
| 玩家携带 | S08 罐装化学品物品（桶/瓶，Forge 标准桶机制） |
| 第三方 mod 流体 | 白拿：所有物种都是标准 Forge Fluid，AE2/MEK/TFMG 管道若支持 Forge 流体即可互通（**TFMG 的油/酸可作联动点**，D15 无机主线不冲突） |
| 世界流体 | 化学流体不放置为世界流体（不泼洒；漏液事故以粒子表现） |

## 8. 关键检验：旗舰场景

1. **索尔维闭环**：氨盐水（注册流体，组合系统定义组成）走 Create 管道入釜 → 釜内转流股 → 碳化反应（进度+中间态 NaHCO₃ 沉淀，固相进浆料）→ 出釜：重碱浆料（流体）→ 沉淀池/过滤机 → 滤饼 item 上带 → 煅烧窑出纯碱+CO₂（气体流体）回收 → 氨回收。**全程可表达，运输层全复用。**
2. **浓硫酸稀释事故**：浓硫酸（流体）与水管同入釜 → 禁忌组合检查 → 温度瞬升+压力骤升 → 事故（可配置爆炸）。**可表达。**
3. **合成氨循环**：N₂+H₂ 气体流体 → 高压釜（流股，20 MPa）→ 转化率 15–20% → 出口气（未反应为主）→ 压缩机增压 → 循环回釜。**可表达。**

## 9. 否决清单（维持/更新）

| 方案 | 否决理由 |
|------|---------|
| 每物种×每状态注册（冷/热/浓/稀全独立） | 组合爆炸（v1 已否决，双轨后彻底不需要） |
| 流股管道网络（v1 方案） | 双轨下失去必要性（§3）；釜内流股不出釜 |
| 世界流体模拟 | 釜内均质相才是化学语义；格子模拟慢且反直觉 |
| 真实热力学/动力学模拟 | 白名单配方+查表是游戏性；科学计算器不是游戏 |
| 任意混合即反应 | 组合爆炸+不可预测（保持白名单+禁忌组合安全网） |
