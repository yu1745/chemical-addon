## 1. 两级结构

```
┌─ 配方层（复用 Create ProcessingRecipe 管线）──────────────┐
│  RecipeType: chemical_reaction（自定义，ProcessingRecipe 派生）│
│  字段：item+fluid 输入 / fluid+item 输出（含概率副产）/       │
│        HeatCondition 门槛 / processingTime / 催化剂物品 /     │
│        自定义字段：压力下限、温度窗口、浓度要求、ΔH           │
│  生态红利：JEI 展示、datagen、ponder、KubeJS-Create 脚本加反应 │
├─ 执行层（自研：釜内流股模拟）─────────────────────────────┤
│  釜内容器：多物种流股共存（匠魂熔炼炉式多流体罐 + 状态）        │
│  模拟：进度 0→100%、分步中间态、温度/压力演化、催化寿命、       │
│       平衡简化（转化率上限/方向切换）、事故检测               │
└──────────────────────────────────────────────────────────┘
```

## 2. 配方数据结构（概念层）

```
chemical_reaction {
  inputs:      [ {fluid: 盐水, amount}, {item: 石灰石, count}, ... ]   // 也可气体流体
  outputs:     [ {fluid: 烧碱液, amount}, {item: 纯碱, chance}, ... ]   // 概率副产同 ProcessingRecipe
  heat:        HEATED | SUPERHEATED | NONE          // Create HeatCondition
  pressure:    { min: 0.1MPa, max: 常压 }            // 自定义（自研）
  temperature: { min: 30°C, max: 60°C }              // 自定义（显示用，热级校验为准）
  catalyst:    { item: 五氧化二钒, durabilityPerUse: 100 }   // 可选
  processingTime: 300  // tick，釜容量放大时吞吐等比放大
  deltaHeat:   +1200   // ΔH：放热为正（釜温升）/ 吸热为负（需供热）
  intermediates: [NaHCO₃]  // 分步反应的中间物种（可选，用于多段配方链）
  requires:    { seal: SEALED }  // 密封等级要求（常压/密封/高压）
  balancing:   { maxConversion: 0.8, reversible: false }  // 平衡简化
}
```

全部字段 JSON 化（KubeJS 可写）；催化剂与密封/压力为自研扩展字段（ProcessingRecipe 的 `extraConditions` 思路）。

## 3. 釜内执行模拟（核心算法，概念层）

每低频 tick（10 tick）执行：

```
1. 匹配：釜内容器流股集合 vs 白名单配方（**自动匹配**，最多同时 1 个主配方 + 0..2 个副配方；匹配失败由 ReactorStatus 诊断）
2. 校验：热级 ≥ 门槛（Blaze Burner/夹套状态）、压力 ∈ 窗口、密封等级、催化剂在位、浓度下限
3. 进度：progress += baseRate × 温度系数 × 搅拌系数 × 规模系数
   - 温度系数：窗口内 1.0，低于下限衰减（0.5/0.25…），高于上限触发危险检查
   - 搅拌系数：转速 0 时 0.3（传质差），满速 1.0；塔式无搅拌用喷淋/鼓泡代替
   - 规模系数：釜容量（方块数）与配方基准量的比值（大釜一次处理更多）
4. 中间态：progress 过 50% 且配方声明 intermediates → 先产出中间物种（如 NaHCO₃ 浆料）再继续
5. 结算：progress ≥ 100% → 消耗输入、产出输出；催化剂扣耐久；ΔH 作用于温度
6. 温度演化：T += ΔH×当次转化量 - 散热（环境/夹套/冷却塔）；放热大则升温→加速（正反馈=热失控风险）
7. 压力演化：密封容器内 气相量×T → P（线性近似）；超限→泄压阀/爆炸
8. 事故检测：禁忌组合检查（如浓硫酸+水并存）、超温分解、腐蚀（无内衬）
```

**设计要点**：
- **放热=玩法**：ΔH 让温度爬升，玩家必须配冷却（夹套/换热器/冷却塔），否则热失控——「反应条件」不是配方字段，而是玩家要搭建的工程；
- **转化率上限**（如合成氨 15–20%）= 强制「循环未反应气体」的闭环教学；
- **分步中间态** = 教学（索尔维碳化的 NaHCO₃ 沉淀是主产物步骤，不是中间态；中间态用于接触法 SO₃、氨氧化 NO→NO₂ 等）。

## 4. 平衡简化（三档）

| 档 | 规则 | 例子 |
|----|------|------|
| 完全正向 | 消耗完输入即完成 | 中和、煅烧 |
| 转化率上限 | 配方达到 maxConversion 后停止消耗（需循环分离） | 合成氨（0.15–0.2）、接触法 SO₂→SO₃（0.95） |
| 条件切换方向 | 温度/压力窗口决定正逆方向 | CO₂ 吸收/解吸、氨水蒸馏 |

不做真实平衡常数计算；每档都是查表+阈值，可表达、可调试、可教学。

## 5. 催化

- 催化剂 = **物品**（V₂O₅ 触媒、铁触媒、铂网），放入釜内 S07 催化剂托盘；
- 效果：降低热级门槛（如接触法 SEETHING→KINDLED）或提高转化率上限；
- 寿命：耐久值，每完成一批配方扣减；可用漏斗/机械臂自动更换（物品物流白拿）。

## 6. 禁忌组合与事故（M10 细化）

| 禁忌 | 判定 | 事故 |
|------|------|------|
| 浓硫酸 + 水 | 釜内并存 | 剧烈放热+飞溅（容器温度瞬升、压力骤升） |
| 氯气 + 氢气（无点火） | 并存+达到燃点 | 爆鸣（小范围爆炸） |
| 次氯酸盐 + 酸 | 并存 | 放出氯气（毒气泄漏） |
| 碱金属?（不引入） | — | — |

判定在釜内流股混合时检查（配方制之外的安全网）；泄漏的毒气进入净化塔可处理（T3 后）；事故强度可配置（仅损物料/破坏结构）。

## 7. 与 Create 配方的边界

- **简单处理**（不涉及温度/压力/中间态）：用 Create 原生配方就行（Mixing/Compacting/Filling），如 盐+水→盐水 用 Mixing、矿物粉碎用 Crushing——**这些不进釜**，玩家用 Create 的搅拌机/粉碎机即可，釜只做"化学反应"；
- **化学反应**（条件/进度/放热）：必须进釜（或电解槽等专用块）；
- 这样釜数量需求下降，Create 原生机器承担前处理，分工清晰（呼应 D6 机器分工，但口径更细）。

## 8. 配方集规模

52 条反应（见 07-reaction-catalog），按模块分组（原料/酸/氯碱/索尔维/合成氨/铝/废料/物理分离），其中：
- ~18 条为 Create 原生配方（溶解/粉碎/结晶等物理过程）；
- ~34 条为 chemical_reaction（釜内反应）。

### 9.1 为什么白名单配方不够

当前（§1–§8）是**白名单配方制**：每条反应一个 JSON，玩家匹配即执行。这对**固定工艺路线**（接触法制硫酸、合成氨、索尔维制碱）够用，但无法覆盖：

- **复分解反应（双置换）**：AB + CD → AD + CB。离子在溶液里重组，组合是**组合爆炸**的——NaCl+AgNO₃、Na₂SO₄+BaCl₂、K₂CO₃+Ca(NO₃)₂…… 每对电解质都可能反应，**不可能为每对白名单一条配方**。
- **条件相关产物**：同样两种物质，温度/浓度不同可能走向不同产物（反应导向）。
- **溶解度驱动的分离**：冷却某溶液 → 溶解度最低的物种先析出（索尔维碳化析出 NaHCO₃、硝酸盐冷却结晶）。这是"按温度除杂/精炼"的核心玩法，**不是固定配方能表达的**——它依赖当前混合物的组分浓度 + 物种溶解度曲线。

→ 需要一个**规则引擎**：从"组分 + 条件"动态推导发生了什么，而不是查表。

### 9.2 规则引擎要做什么

| 能力 | 机制 | 例子 |
|------|------|------|
| **电解质解离模型** | 酸/碱/可溶盐在溶液里解离成离子（数据驱动：物种 JSON 标注可解离 + 离子组成） | NaCl → Na⁺ + Cl⁻；H₂SO₄ → 2H⁺ + SO₄²⁻ |
| **复分解判定** | 混合物内离子重组，查"产物溶解度/气体/水"规则决定是否反应、生成什么 | Na⁺+Cl⁻+Ag⁺+NO₃⁻ → AgCl↓（沉淀）+ NaNO₃（留液） |
| **沉淀规则** | 难溶离子对按 Ksp 由低到高析出，进 `Suspended` 混悬域（釜内浑浊、不澄清，过滤机抽走） | Ba²⁺+SO₄²⁻ 浓度积超 Ksp → BaSO₄ 混悬 |
| **冷却析出** | 温度下降 → 溶解度曲线下降 → 过饱和组分结晶析出，进 `Sediment` 沉底域（直接沉底） | 冷却氨盐水 → NaHCO₃ 析出（索尔维碳化塔）；冷却 KNO₃ 溶液结晶 |
| **反应导向** | 同样输入，根据温度窗口/浓度/催化选择主反应路径 | CO₂ 在不同温度下水化成碳酸 vs 解吸；氨氧化 NO→NO₂ 需催化窗口 |
| **平衡/可逆** | 部分反应有转化率上限或可逆（温度切换方向），引擎按规则收敛而非一次到底 | 合成氨转化率上限；CO₂ 吸收/解吸 |

### 9.3 数据驱动（避免硬编码）

物种 JSON（`data/<mod>/chemistry/species/*.json`）扩展字段（数据包可覆盖）：
```
species: {
  ... 现有字段 ...,
  dissociation: [ { ion: "Na+", count: 1 }, { ion: "Cl-", count: 1 } ],  // 可解离物种
  solubility: [ { tempC: 0, gPer100g: 35.7 }, { tempC: 100, gPer100g: 39.1 } ], // 溶解度曲线（插值）
  ksp: 1.8e-10,  // 难溶物溶度积（用于沉淀判定，可选）
  phase_transition: [ { tempC: 801, to: "molten_nacl" } ]  // 相变（熔化/汽化）
}
```
规则引擎读取这些，在混合物流体（已有 Components + Temperature）上跑：每低频 tick，解离→离子重组→沉淀/析出检查→更新混合物组分（消耗参与物种、移除析出物到固相、调整浓度）。

### 9.4 与现有白名单配方的关系

- **白名单配方（§1–§8）继续用于固定工艺路线**（接触法、合成氨、索尔维主流程等"教学/主线"反应）——它们有明确的进度/ΔH/催化，适合 ProcessingRecipe 表达。
- **规则引擎处理"开放组合"**（复分解、溶解度析出、相变）——这些是涌现的、组合的，不该也不必白名单。
- 两套并存：釜每 tick 先跑规则引擎（涌现化学），再匹配白名单配方（人工设计的工艺）。规则引擎的产物可以成为白名单配方的输入。

### 9.5 实现门槛与依赖

- **强依赖混合物流体**（Components + Temperature + 浓度推导）——所以混合流体必须先做。
- **依赖溶解度/解离数据**——需扩展物种 JSON schema 并补数据（gen_species.py 数据表加列）。
- **复杂度高**：离子重组 + Ksp 判定 + 溶解度插值 + 相变，是本项目最大的机制块。
- **分阶段**：先做"溶解度冷却析出"（索尔维教学最急需），再做"复分解/沉淀"（规则最多），最后"反应导向/相变"。

### 9.6 相界约束：反应只在同一互溶相内发生（互溶性概念，见 [03 §5.4](03-substance-model.md)）

- **解离 / 复分解 / 沉淀 / 冷却析出都只在一个互溶相内求解**：离子不跨相界，油水两相里的离子各算各的，不会「跨杯」重组。这天然把规则引擎的组合搜索**按相分组**，既是化学直觉（不互溶即不共享溶剂），也是性能护栏。
- **不互溶两相只在界面反应**（如油相+水相的萃取/皂化），需要釜内**搅拌**增大接触面积——搅拌系数（§3）此时既是传质也是「跨相反应」的开关。
- **实现含义**：规则引擎以「一个 `mixture` FluidStack（= 一个互溶相）」为求解单元循环；跨相反应作为独立的「界面配方」类型，由搅拌/接触条件触发，不进离子重组搜索。

> ⚠️ 这是**远期但非常重要**的部分，是"模拟真实化学"的兑现点。混合流体系统 + 互溶性概念是它的前置地基。

## 10. 运行模式：批式 / 连续流（流态范式）

> 原 13-flow-modes.md 已并入本节（引擎语义）与 [04-machines.md](04-machines.md) §5（S11–S15 规格）；落地单元 = [11-content-scope.md](11-content-scope.md) §2.1 的 U5（F1 批式）/ U8（F2 连续流）/ U9（F3 旗舰接线）。本文 §3 的釜内执行模拟目前是**批式原生**（进度 0→100% 一次性结算清空）。

两个正交层：**执行层**（引擎语义：攒满结算 or 分率转化）= 容器 `mode: BATCH|CONTINUOUS` 字段；**控制层**（谁测状态、谁判时机、谁开关阀泵）= S11–S15 + Create 红石（见 04 §5 注记）。

**批式（BATCH）**：四相状态机，周期 = t_fill + t_react + t_drain + t_flush——S13 定量投料 → S11 满检测启动 → S12 完成触发排空 → S11 空检测 + 定时复位；引擎语义照旧。

**连续流（CONTINUOUS）**：节拍 = **停留时间 τ = V/Q**（罐容/流量）；进料速率 = 出料速率，液位由 S14 溢流堰被动自稳；**每 tick 按 τ 转化一个分率（转化率 = f(τ)）**，产物 + 未反应进料一起流出、下游分离/循环（合成氨 15–20% 转化率即此模型的产物）；沉淀连续累积进 `Suspended`、底部连续抽浆。连续模式**无「完成」态**——S12 的完成语义只属批式，连续模式诊断态 = 稳态/扰动/排空。

引擎分支落在 `tickReaction`：`mode=BATCH` 走现有进度结算（注意现行 `completeRecipe` 对每个 ingredient 固定消耗 1 个，批式语义内嵌）；`mode=CONTINUOUS` 走分率转化 + **比例消耗** + 出流。

已知风险：低频结算（10 tick）下分率转化的**离散误差**需 GameTest 量化（τ ≫ tick 时可忽略）；τ 太短 → 进料未反应完即流出 → 必须循环。
