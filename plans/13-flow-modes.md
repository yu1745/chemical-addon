## 0. 问题：引擎是批式原生的，但旗舰流程是连续流

- 现有反应引擎（06 §3）只有一种语义：匹配 → `progress` 0→100% → **一次性结算清空**。这是**批式原生**。
- 但旗舰场景多数是**连续流**：
  - 索尔维碳化塔（逆流气液吸收 + 连续析出 NaHCO₃↓）
  - 蒸氨塔、石灰窑（M16 连续进出料）
  - 合成氨高压釜（转化率 15–20%，未反应气**连续循环**）
- 结论：连续流不是「可选优化」，是 T2 索尔维 / T3 合成氨闭环的**引擎层刚需**。

## 1. 两个正交层

节拍控制拆成两层，避免混淆：

| 层 | 回答的问题 | 承载 |
|----|-----------|------|
| **执行层（引擎语义）** | 反应是「攒满结算」还是「每 tick 转化分率、未反应物随流出」？ | 容器状态加 `mode` 字段（§4） |
| **控制层（方块/红石）** | 谁测状态、谁判时机、谁开关阀/泵/离合？ | S11–S15 + Create 红石（§5–§7） |

通用控制链：**测量（传感器）→ 决策（红石逻辑）→ 执行（阀门/泵/离合）**。与 AGENTS.md 基调一致——红石即编程语言，控制零 GUI。

## 2. 批式（Batch）

周期 = `投料 → 反应 → 排空 → 清洗/复位 → 投料…`，一个**四相状态机**。

| 相 | 触发 | 需要的信号 |
|----|------|-----------|
| 投料 | 上一周期结束 | 计量投料 S13（定量注入） |
| 反应 | 投料满 | 液位计 S11（满检测）→ 启动 |
| 排空 | 反应完成 | 反应状态接口 S12（progress=100% / ReactorStatus） |
| 复位/清洗 | 排空 | 液位计 S11（空检测）+ 定时（清洗时长） |

节拍周期 = `t_fill + t_react + t_drain + t_flush`。前三相由**传感器触发**，第四相由**定时器**给。

## 3. 连续流（Continuous）

没有「一池一池」，节拍 = **停留时间 τ = V / Q**（罐容 / 流量）。

- 进料速率 = 出料速率；液位由**溢流 / 液位调节**自稳（S14）。
- 反应不是「攒满结算」，而是**每 tick 按停留时间转化一个分率**；产物 + 未反应进料**一起流出**，下游分离/循环。
- 沉淀（NaHCO₃↓）连续累积进 `Suspended` 域，底部当浆料连续抽走。
- 引擎需加停留时间模型：**转化率 = f(τ)**；τ 太短 → 进料未反应完即流出 → 必须循环（合成氨 15–20% 转化率正是此模型的产物）。

## 4. 引擎 `mode` 字段（执行层核心改动）

容器状态加 `mode: BATCH | CONTINUOUS`（由端口/程控器配置决定，`tickReaction` 分支）：

| 维度 | 批式 | 连续流 |
|------|------|--------|
| 进度语义 | 0→100% 一次性结算清空 | 每 tick 分率转化（转化率=f(τ)） |
| 出流 | 封闭到结束 | 产物 + 未反应进料连续流出 |
| 「完成」触发 | progress≥100% | 永不「完成」，进料停即停 |
| 液位 | 满/空 = 节拍触发 | 溢流/液位调节维持稳态 |
| 沉淀 | 结算时写入 Suspended | 连续累积、连续抽浆 |
| 教学落点 | 中和、接触法 SO₂→SO₃ | 索尔维碳化塔、合成氨循环 |

> 落地顺序建议：先批式（现有语义已近，补 S11–S13 + S15 即可闭环），再连续流（引擎 `mode` 分支 + 停留时间模型 + S14），随 M3 索尔维/合成氨一并交付。

## 5. 控制原语（测量 → 决策 → 执行）

### 5.1 测量（传感器）
- 温度/压力/浓度：已有 S02 / S03 / S04。
- **液位**：S11（新增，补 Create 没有的流体阈值）。
- **反应完成/进度**：S12（新增，把 ReactorStatus 映射为红石）。

### 5.2 决策
- 复用原版红石（比较器/中继器/脉冲延长器）+ Create 阈值开关、红石链接、Sequenced Gearshift。
- 批式四相时序可手搓，或打包进 S15。

### 5.3 执行
- Smart Fluid Pipe / 机械泵 + **离合 Clutch** = 启停阀门/泵。
- 计量注入 S13、溢流 S14。

## 6. 新增方块（S 系列延续，自研小件）

| ID | 名称 | 功能 | 服务模式 |
|----|------|------|---------|
| S11 | **液位计** | 贴面读容器总液量/各相液位；红石阈值输出 + 比较器模拟信号（针对流体的阈值开关，补 Create 缺失的流体维度） | 两者 |
| S12 | **反应状态接口** | 把 `ReactorStatus`（未成型/反应中/温度不满足/输出满/无匹配配方）与进度映射为红石电平/比较器模拟；「反应完成」是批式核心触发点 | 批式 |
| S13 | **计量投料口** | 红石脉冲触发，按 `ScrollValueBehaviour` 设定量精确注入 N mB（批式投料不靠「灌到满」，靠定量） | 批式 |
| S14 | **溢流口** | 连续模式被动自稳：液位超设定值即溢流排出（物理堰，无需红石），对标 CSTR 溢流堰 | 连续流 |
| S15 | **批次程控器** | 四相节拍器：`投料→反应→排空→复位` 四个红石相输出，各相时长用世界内滚动调值；红石输入：使能/中止/手动进相 | 批式 |

> 设计约束（AGENTS.md 铁律）：S15 不是 GUI 编程面板——它是把玩家手搓时序**打包**的世界内方块，相时长是滚动数值（`ScrollValueBehaviour`，符合「离散数值用滚动调值」例外条款①），外部红石完全互通。玩家可直接用 S15，也可全程手搓红石实现同效果，两种玩法并存。

## 8. 落点

- **索尔维碳化塔（T2）**：连续流 + 逆流气液吸收 + Suspended 连续析出 NaHCO₃ → 底部连续抽浆 → 过滤机。连续流模式的首个教学关。
- **合成氨（T3）**：连续流高压釜，转化率 15–20% → 未反应气连续循环（§4 停留时间模型落地）。
- **中和 / 接触法 SO₂→SO₃（T1/T2）**：批式，四相状态机（S11/S12/S13/S15）首次教学。

## 10. 风险与开放问题

- **停留时间模型的分辨率**：连续流「分率转化」在低频结算（10 tick）下的离散误差，需验证是否可接受（τ 远大于 tick 时近似可忽略）。
- **连续流的「完成」缺失**：S12 的「反应完成」在连续模式无意义，需定义连续模式的诊断态（稳态/扰动/排空）。
- **与 D18 分相的耦合**：连续流出相的选择依赖 03 §2.2 的密度排序抽相，F2 依赖 D18 落地。
- **计量精度**：S13 的 N mB 精确注入与电中性校验（03 §2.1）的边界需在 F1 明确。
